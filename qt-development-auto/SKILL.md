# Qt 开发统一入口

根据用户目标自动选择和组合内置的十三个模块。用户只需描述任务，无需选择模块名称，也无需另行安装原来的十三个技能。

## 自动选择

1. 先判断交付物、任务范围，以及现有项目使用的 Qt 版本、界面技术和构建方式；已有代码和项目约定优先。
2. 从下表选择一个主模块；只有当前任务确实需要时才补充其他模块。简短说明选择理由后继续执行，不把模块菜单交给用户选择。
3. 完整读取所选模块的中文说明和其中链接的原始说明，再按原始流程读取必要的参考、示例或脚本。不要预先读取全部十三个模块。
4. 按用户请求完成工作，使用适合改动范围的验证，区分实际执行结果、静态检查和未完成的验证。

## 组合规则

- 新建 Qt Quick 应用：以项目配置和 QML 开发为主；需要界面设计时补充界面设计模块。现有 Qt Widgets 项目沿用原技术，不自动改写为 QML。
- 修改 QML：使用 QML 开发；只有涉及自定义二维绘图时才补充二维画布。普通修改不自动扩展为全项目审查、性能采集或文档工程。
- 代码审查：按实际语言选择一个或两个审查模块，必要时参照 QML 开发规则。审查保持只读；不自动修复、启动预览或修改构建配置。
- 编写并运行测试：先生成测试，再运行测试。仅要求运行时，使用现有测试；没有测试就报告现状，不自动生成测试或改造构建。
- 性能任务：已有轨迹先分析轨迹；需要复现和采集时再运行应用。该性能模块只覆盖二维 Qt Quick，不能据此宣称完成 Qt Quick 3D 分析。
- 文档任务：只加载相应语言的文档模块；明确区分 Markdown 参考文档与 QDoc，用户要求 QDoc 时不套用 Markdown 输出格式。
- Figma 转 QML：缺少设计令牌时先提取，再生成组件；已有可用的令牌和单例时直接生成组件。按组件逐个检查状态与变体，不仅凭截图臆测完整行为。

## 内置资料的路径

- 本文件所在目录是统一技能根目录。`modules/<模块名>/` 是该模块的目录。
- 每个模块的 `原始说明.txt` 完整保留上游 `SKILL.md`，作为按需读取的内部流程，不是独立技能入口。该原文中的 `<skill>`、`<skill-path>`、技能目录、相对路径均指向当前模块目录。
- 原文提及其他 `qt-*` 技能时，按上表转到对应的兄弟模块；不要要求用户安装独立技能。原文要求读取当前 `SKILL.md` 时，读取当前模块的 `原始说明.txt`。
- 示例、脚本、参考和许可证保留原有相对目录。运行脚本时构造其实际路径，不依赖已删除的独立安装目录。
- 上游所述专用代理或平台适配不是额外安装要求。遵守当前环境关于代理与工具的规则；没有专用代理时在当前执行环境完成适用的分析。

## 执行边界

- 用户指令、项目约定及更高优先级规则优先。新生成的说明、文档、注释、审查报告和提交信息使用简体中文；代码标识符、命令、API 和上游原始资料保持必要原文。
- 保持用户要求的范围。审查与文档任务不隐含修改源码；新增测试接线、调整根构建文件等以已有授权为准，不能由模块选择扩大权限。
- 结合实际安装的 Qt 版本选择 API。Canvas2D 和部分预览能力有 Qt 6.12 版本要求；项目的最低版本声明不等于本机实际版本。已有渲染器明确时不擅自迁移。
- Qt SDK、编译器、`qmltestrunner`、`qmlprofiler`、系统 `qmllint`、预览与 Figma 连接按任务检查是否可用。技能安装不代表这些外部依赖已经安装或连接。
- 缺少工具时完成可做的代码或静态分析，说明未执行的构建、测试或采集；不能将脚本检查通过描述为应用已运行通过。
- Figma 使用当前可用且已授权的连接或本地导出资料；不要要求用户在聊天中发送密钥，也不擅自写回设计文件。
- 使用实际源码、日志和工具输出支持结论。保留原始诊断信息的含义，以中文解释，审查问题附真实文件与行号。

需要维护模块来源或核对文件完整性时，读取[来源与维护](references/来源与维护.md)。
