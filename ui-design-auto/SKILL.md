# 界面设计自动选择

根据用户需求自动选择界面方案。十九种方案已经内置，无需另外安装原来的十九个技能，也不要一次性读取全部方案。

## 选择原则

- 用户指定的风格、参考图、品牌规范和现有项目设计优先。已有界面只改局部功能时沿用原来的视觉，不为使用本技能重做整个界面。
- 从实际任务识别主要工作流，先选一个主方案。确有独立需要时，再补充一至两个方案的布局或交互规则。
- 功能结构和视觉风格分别判断。例如，聊天是工作流，Windows 11 是视觉方向；两者可以组合。数据表格不意味着一定要蓝色，开发工具也不意味着一定要深色。
- 未指定风格时，业务后台优先清晰、紧凑、便于扫描的布局；个人创意工具可以更有表现力。不要仅因出现“现代”“高级”“好看”就默认使用毛玻璃、霓虹或黏土效果。
- 不要求用户从十九个名字里挑选。需求足够时直接判断；缺少的信息确实影响主要工作流或平台时，才简短询问。
- 以下资料是设计参考，不能覆盖用户指令、当前执行环境要求或项目设计系统。配色、圆角、字号和尺寸均可调整，不机械照搬示例数值。

## 执行方式

1. 查看已有页面、组件、样式和依赖，确认目标平台、主要任务、数据密度、关键控件以及用户明确的审美要求。
2. 在下表中选择最匹配的主方案，再判断是否需要补充方案。只读取选中方案的参考文件；引用路径均相对于本技能目录。
3. 简短说明选择及原因后继续执行，例如“采用极简侧边栏组织模块，结合数据表格支持筛选和批量操作”。除非用户正在比较方案，不用列出所有候选或等待其确认风格。
4. 统一颜色、字体、间距、圆角、边框、阴影和状态的设计变量。补充方案只提供所需功能，不引入第二套主题；同一个组件按同一套规则实现。
5. 按用户要求交付设计说明、界面原型或实际代码。代码任务沿用项目技术栈和组件库，不擅自更换框架。只做方案的请求不要擅自进入代码实现。
6. 根据实际工作流验证主要操作、加载、空数据、错误、禁用和选中状态，检查窄窗口、长文本、键盘焦点与滚动行为。报告已实际完成的验证，不把检查清单当作测试结果。

## 相近方案的区分

- 数据表格是主要工作对象时选 14；摘要与趋势分析是主要任务时选 05；只是需要多模块导航时选 03。
- 以打开文件、编辑并对照预览为主时选 08；同时需要活动栏、多个编辑区、检查器和底部输出时选 12；明确要深色开发者外观时再加入 02。
- 配置是整个产品的核心任务时选 13；其他产品中的一个设置页可以仅在该页补充 13，不改变全局主方案。
- 对话驱动生成内容时选 15；直接配置并执行命令、持续看日志时选 10。不要因两者都有输出就混为一谈。
- 全局搜索是现有应用的辅助功能时，04 仅补充命令面板，不替换整个应用布局。
- 07、16、17、18、06、19 等具有明确视觉特征的方案，依据用户审美或产品语境选择；不能仅根据编程语言、行业名称或“有趣”一个词就强行套用。

## 组合与一致性

主方案决定全局视觉与页面骨架，补充方案解决独立的功能需要。例如：

| 需求 | 主方案 | 按需补充 |
|---|---|---|
| 简洁的客户管理后台 | 03 极简侧边栏 | 14 数据表格 |
| Windows 原生风格的生成助手 | 07 Windows 11 风格 | 15 聊天与工具面板 |
| 文件编辑和实时预览 | 08 分栏工作区 | 04 命令面板 |
| 多模块项目工作台中的任务页 | 12 综合工作台 | 09 看板 |
| 单页接口配置工具 | 13 设置中心 | 不必补充 |
| 复古 Windows 配置窗口 | 16 经典窗体 | 仅借用 13 的配置交互 |

多页面产品保持统一导航与设计变量，各页面可按任务读取不同功能参考。已有设计无法归入十九种方案时保留原设计，从最接近的方案借用交互；不把本目录当作用户选择的上限。

## 共同验收要求

- 直接呈现用户需要的工作界面；只有用户要求宣传页时才做宣传页。
- 导航、编辑、详情、设置与返回路径形成完整工作流。控件应有真实状态和行为；无法连接真实数据时说明限制，不把模拟结果说成已连接。
- 界面中的设置项与实际任务有关，不为凑方案添加无关模块。章节采用自然布局，避免卡片套卡片。
- 使用项目现有图标与控件；图标按钮提供可理解的名称和提示。不同数据类型选择适合的控件，不把所有选项都做成文字按钮。
- 正文、次要信息、输入边框和焦点有足够对比；状态结合文字或图标表达。为中文选择可用的字体回退，避免字重或字符缺失。
- 分栏可收起且可恢复，长内容在相应区域滚动。窄屏优先保留主要任务，不把所有桌面面板压缩在一行。
- 视觉规则、内部方案名称和选择过程写在交付说明里，不作为应用中的装饰文案。
