# 可编辑PPT工作室

## 总原则

将 `officecli` 作为最终 PPTX 的创建、修改和保存引擎。正常文字必须为原生文本，常规图表必须为原生图表，流程图/表格/卡片必须优先为原生形状或表格；图片、背景、照片、插画和纹理作为可替换的独立图片对象。

禁止将包含标题、正文、关键数据或图表标签的整页图片作为最终交付。图片对象本身可移动、缩放、裁剪和替换，但不承诺将 AI 图片自动变成可编辑矢量路径。

收到任务后只询问会显著改变结果的缺失信息。未指定时，使用 16:9、简体中文、适合受众的专业风格，并根据内容推断合理页数。

## 启动前依赖预检

在分析大纲、生成任何图片或创建任何 PPTX 之前，先识别输入路线及是否需要图片、模板、图片还原和动画，再一次性检查该任务所需的全部依赖。预检通过前不得开始制作；任一必需依赖不可读、未暴露、缺少所需命令、能力不支持或环境未就绪时，立即报告具体依赖与原因，并停止等待处理。

| 条件 | 必须检查的依赖 |
|---|---|
| 所有 PPTX 任务 | `officecli` 技能、OfficeCLI 环境、`pptx` 创建/修改/校验能力 |
| 逐页规格需要图片、背景、插画或装饰 | `imagegen` 技能和当前任务可用的图片生成能力 |
| 输入为图片版 PPT、截图、扫描页或渲染型 PDF | `GordenImage2PPTX` 技能、其脚本和 `imagegen` |
| 已判定需要复杂对象动画 | `ppt-master` 动画工作流和其所需导出能力 |
| 需要借用高保真视觉规划方法 | `awesome-ppt` 技能 |

必须读取每个将要调用的技能的 `SKILL.md`，并用一次最小能力检查验证实际可用性。不要把“路径存在”当作可用。预检结果须在开始制作前简要列出“可用依赖”和“本任务不会调用的依赖”。

## OfficeCLI 主路径

每次处理 PPTX 前，先读取并遵循 `C:\Users\PC\.codex\skills\officecli\SKILL.md`：运行其环境修复与就绪检查，查看当前版本的 `pptx` 能力说明。

- 若 `officecli` 已就绪且支持所需操作，必须用其生成或修改最终 PPTX。
- 若能力检查、环境修复或生成失败，明确说明原因并停止；不得悄悄改用其他工具生成最终文件。
- 可使用其他工具生成图片、解析材料、检查文件或完成辅助分析，但不得替代 `officecli` 的最终 PPTX 路径。

## 图片风格确认

当逐页规格需要生成图片，且用户未明确确认可直接采用的视觉风格时，必须在生成正式图片前暂停，先为同一主题生成三张低成本的风格预览图。三种方案必须有可辨识的差异，例如：极简编辑感、商业摄影感、叙事插画感；每张预览均以同一核心内容展示，方便比较构图、色彩、材质和视觉语气。

将三张预览及其简短风格名称展示给用户，等待用户选择、组合或提出修改。只有收到确认后，才将选定风格锁定到所有正式图片提示词并继续生成背景、插画、照片和装饰素材。

- 用户已明确指定视觉风格时，仍先简短复述该风格并请求确认；用户明确说“按此风格直接生成”时可跳过预览。
- 风格预览仅用于选择方向，不能直接作为正式 PPT 背景或整页内容。
- 用户改变风格后，作废未确认的正式图片提示词，重新按新风格生成预览或正式素材。

## 路线选择

根据输入自动选择一条主路线：

| 输入 | 主路线 |
|---|---|
| 主题、文本、文档、数据或网页材料 | 从零原生制作 |
| 现有 PPTX、POTX 或品牌模板 | 模板原生编辑 |
| 幻灯片截图、图片版 PPT、扫描页或渲染型 PDF | 图片版还原 |

## 从零原生制作

依次完成以下步骤，不要求用户在步骤间切换技能：

1. 分析来源，确定受众、目标、核心结论、数据证据、品牌约束和演示场景。
2. 自动写出大纲与逐页规格：每页只承担一个表达任务，并列出原生文字、形状、图表、表格、图片和动画需求。
3. 需要照片、插画、纹理、背景或装饰时，先完成图片风格确认，再读取并遵循 `C:\Users\PC\.codex\skills\.system\imagegen\SKILL.md`。每张素材单独生成与保存；提示词不得承载普通文字、标题、关键数据或图表标签。
4. 使用 `officecli` 创建最终 PPTX，将文字、表格、形状、图表和图片作为独立对象写入。以原生图表表达 PowerPoint 支持的数据关系；避免将图表渲染为图片。
5. 应用动画判断规则并进行质量检查，修复所有可见问题后交付。

可读取 `C:\Users\PC\.codex\skills\awesome-ppt\SKILL.md` 获取视觉方向、页面叙事和图片提示词方法，但绝不采用其“整页图片作为最终内容”的路线。

## 模板原生编辑

先读取现有模板的页面、元素和文本结构，再将内容映射到合适版式。保留有价值的模板组合；当内容数量不匹配时，删除完整的占位组合，不留下孤立形状、图片或占位文字。

使用 `officecli` 编辑最终 PPTX。新增的文字、图表、表格、形状和图片必须保持原生独立对象，且不得破坏模板的主题、关系或文件结构。

## 图片版还原

当输入是截图、扫描页、图片版 PPT 或渲染型 PDF 时，先读取并遵循 `C:\Users\PC\.codex\skills\GordenImage2PPTX\SKILL.md`。

对每页按背景、框架、图标/装饰、文字四层进行还原：普通文字转为原生文本框，背景/框架/图标/艺术字保留为独立图片对象。完成后用 `officecli` 修正内容、补齐原生可编辑对象、写入动画并保存最终 PPTX。

不要直接用原截图作全页背景后叠字；不要把图片层声称为已转成原生矢量形状。

## 动画判断与制作

将动画设为可选但自动判断：

- 用户明确要求“带动画”“转场”“逐步出现”，或任务是演讲、路演、培训、发布会时，自动启用动画。
- 普通汇报、阅读、打印和存档用途默认不加动画。
- 用户可用“不要动画”“只要转场”“对象逐步出现”等明确指令覆盖自动判断。

启用动画时，默认使用克制的页间淡化或推进转场，并按讲述顺序让标题、关键结论、图表和步骤逐步出现。每页都必须有明确的转场效果与时长。

复杂的逐对象动画、时序编排或效果覆盖时，读取并遵循 `C:\Users\PC\.codex\skills\ppt-master\workflows\customize-animations.md`。只对真实可编辑对象或真实 SVG 分组施加动画，不得对整页截图伪造对象动画；完成后必须重新导出最终 PPTX。

## 质量门禁

交付前完成以下检查：

1. 使用 `officecli` 校验最终 PPTX 的 OpenXML 结构，确认文件可打开且无关系、图表或幻灯片错误。
2. 检查全部文本、页序、数据和模板残留，确保无遗漏、乱码、占位符或错误内容。
3. 渲染并检查每页，修复文字溢出、遮挡、裁切、低对比、错位、边距不足和图表不可读问题。
4. 抽查可编辑性：标题、正文、关键图表/形状和图片必须分别存在，不能只有一张覆盖整页的图片。
5. 启用动画时，确认最终文件已写入相应转场与对象动画，并在交付中简述实际动画范围。

最终仅交付完成的 PPTX、需要保留的独立图片素材和必要的可编辑项目文件，并如实说明无法自动化的细微视觉差异。
