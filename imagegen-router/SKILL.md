# 生图路由器

通过本地 `imagegen-router` 应用调用用户配置的 OpenAI 兼容图片供应商。

## 使用边界

- 只处理图片生成、图片编辑和批量生图。
- 不修改系统 `$imagegen` Skill。
- 不读取、修改或覆盖 `cc-switch` 的配置、数据库和运行状态。
- 不修改 `~/.codex/auth.json`、`~/.codex/config.toml`，也不写入全局 API 环境变量。
- 不要求用户在聊天中提供 API Key；供应商密钥由本地应用独立管理。

## 对外接口

本地服务默认地址为 `http://127.0.0.1:8765`，只使用以下接口：

- 文生图：`POST /v1/images/generations`，请求体为 JSON。
- 图生图：`POST /v1/images/edits`，请求体为标准 `multipart/form-data`。
- 任务查询：`GET /api/tasks`，仅用于确认未返回的原始请求状态。

文生图常用字段：`model`、`prompt`、`n`、`size`、`quality`、`response_format`、`background`。

图生图常用字段：`image`、`prompt`、可选的 `mask`，以及 `model`、`n`、`size`、`quality`、`response_format`、`background`。

图片写请求应携带 `Idempotency-Key` 请求头。路由器会用该标识防止同一请求被重复提交；已完成请求会返回首次结果，执行中的请求会返回冲突提示。

## 工作方式

1. 判断任务是文生图、图片编辑还是批量生图。
2. 读取并遵循 [提示词整理规范](references/prompting.md)，把用户的自然语言整理成清晰、可执行的生图提示词。
3. 保留用户明确给出的主体、风格、构图、文字和编辑约束，不凭空添加品牌、人物或无关要求。
4. 只调用上面的本地图片接口，不直接请求外部供应商。
5. 让本地路由器负责供应商选择、模型映射、重试、失败转移和密钥注入。不要在 Skill 内部手动选择或切换供应商。
6. 生成完成后检查返回结果和文件是否有效，向用户报告实际结果。

## 请求约束

不要为了“优化”而改写用户明确给出的图片、蒙版、尺寸、质量或数量参数。图生图上传文件必须直接作为 `multipart/form-data` 的 `image` 字段传递，不要在 Skill 内部额外转换成 Base64。

## 单次请求和等待

- 用户未明确要求批量或多张图片时，只发送一次图片写请求，并显式传递 `n: 1`。
- 为每次用户请求生成一个新的 UUID 作为 `Idempotency-Key`；同一请求的重连或重试必须复用该标识，不得重新生成图片、变体或验证图。
- 客户端等待上限不得短于 10 分钟。连接超时或未收到响应时，先查询任务记录确认原请求状态；不得因为超时自动再次提交。

## 结果展示

- 生成成功后必须返回图片的绝对路径或本地服务返回的可用文件路径。
- 确认文件存在后，在最终结果中展示生成图片；批量任务逐张展示或提供逐张路径。
- 同时说明任务使用的统一模型名、实际供应商（如果路由器返回）、尺寸、质量和失败重试情况。
- 供应商失败时说明已自动转移或任务失败，不暴露 API Key、Authorization 头或敏感日志。

## 供应商兼容性

- “拉取模型”只能检查供应商的模型列表连接并供用户选择模型，不能据此认定图片生成可用。
- 文生图与图生图兼容性需分别在供应商页面的“兼容性检测”中进行真实测试，可能消耗供应商额度。
- 图生图检测可用后，才能开启“参与图生图路由”。供应商模型变更后，两种生图检测状态会重置，需要按新模型重新检测。

## 服务不可用时

如果 `127.0.0.1:8765` 无法连接，提示用户先启动 `imagegen-router` 应用。不要改用 `$imagegen`，除非用户明确要求改用内置生图能力。

如果接口返回认证、参数或模型不支持错误，原样保留安全的错误摘要并停止；网络超时、429 和 5xx 等可恢复错误由本地路由器负责切换和重试。
